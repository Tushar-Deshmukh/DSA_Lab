## The contract {theory}

@pull Recursive thinking: the contract

Here is the contract at work on something familiar. The task: the sum of an array.

```js
// contract: sum(a, i) returns a[i] + a[i+1] + … + a[a.length - 1]
function sum(a, i = 0) {
  if (i === a.length) return 0;      // base case: the empty suffix sums to 0
  return a[i] + sum(a, i + 1);       // transition: trust sum(a, i + 1)
}
```

You do not trace `sum(a, 1)` in your head. Its contract says what it returns, so `a[i] + sum(a, i + 1)` is correct by definition, provided the base case is right and `i` moves towards `a.length` (progress).

```ex

tag: Recursive flatten
q: "Write `flatten(arr)`: return a new array containing every number in `arr`, which may contain nested arrays to any depth, in left-to-right order. Write the contract as a comment first. Do not use `Array.prototype.flat`."

starter: |

  }
solution: |
  // contract: flatten(arr) returns all numbers in arr, in order, with nesting removed
  function flatten(arr) {
    const out = [];

  }
```

```ex
type: code
tag: With an explicit stack
q: "Now write `flattenIter(arr)` with no recursion at all, using an explicit stack. Same output order."
fn: flattenIter
starter: |
  function flattenIter(arr) {

  }
solution: |
  function flattenIter(arr) {
    const out = [], stack = [[arr, 0]];          // [array, next index]
    while (stack.length) {
      const top = stack[stack.length - 1];
      const [a, i] = top;
      if (i === a.length) { stack.pop(); continue; }
      top[1]++;
      if (Array.isArray(a[i])) stack.push([a[i], 0]);
      else out.push(a[i]);
    }
    return out;
  }
tests:
  - { args: [[1, [2, [3, 4]], 5]], expect: [1, 2, 3, 4, 5] }
  - { args: [[]], expect: [] }
  - { args: [[[[[1]]]]], expect: [1] }
  - { args: [[[], [1, []], 2]], expect: [1, 2], hidden: true }
explain: "The stack holds exactly what the call stack held: which array each pending call was in, and where it had got to. An alternative is to push elements in reverse order and pop one at a time."
hints:
  - "Each stack entry needs the array and the position you have reached in it."
  - "When an entry's position reaches the end of its array, pop it."
```

For subsets, the three questions have two good sets of answers, and they give the two methods:

| | Way A: include/exclude | Way B: choose the next element |
| --- | --- | --- |
| Decision per level | take `nums[i]` or skip it | which element comes next (from `start` on) |
| Parameters | `i` | `start` |
| When complete | `i === n` (record at leaves) | every node is a subset (record on entry) |

## Constrained generation: parentheses {theory}

Generate Parentheses (22) could be solved by generating every string of `(` and `)` and filtering the valid ones: 2²ⁿ strings. The better state is two counts. ## String backtracking: Palindrome Partitioning (Stretch) {theory}

Problem 131 asks for every way to cut a string into palindromic pieces. The decision at each level is **where the next piece ends**: from `start`, try every `end` such that `s[start..end]` is a palindrome, push that piece, recurse from `end + 1`, pop. Record when `start` reaches the end of the string.
