## Guided interview problem {guided}

Run this one with the clock: say the clarifying questions, then the brute force, before opening the hints.

```ex
type: interview
title: Maximum Points You Can Obtain from Cards (LeetCode 1423)
q: "Cards are in a row with points `cardPoints`. In each of exactly k steps you take one card from the left end or the right end. Return the maximum total. Example: `[1,2,3,4,5,6,1]`, k = 3 → 12."
model:
  clarify: |
    - Exactly k cards, 1 ≤ k ≤ n ≤ 10⁵; points are positive.
    - Only the ends: you can never take from the middle.
  brute: "Recursion choosing left or right k times: 2ᵏ. Better brute force: for each l from 0 to k, take l from the left and k − l from the right, each sum computed in O(k): O(k²)."
  optimize: |
    Whatever you take, the cards left behind form one **contiguous** block of n − k cards. Maximising what you take = minimising that block, which is a fixed-size sliding window of length n − k: O(n). Equivalently, slide l from 0 to k keeping a running left sum and right sum: O(k).
  edges: |
    - k = n → take everything
    - the best answer takes all from one side
    - a large value hidden in the middle cannot be reached
  complexity: "O(n) time (or O(k)), O(1) space."
fn: maxScore
starter: |
  function maxScore(cardPoints, k) {

  }
solution: |
  function maxScore(cardPoints, k) {
    const n = cardPoints.length, w = n - k;
    let total = 0, win = 0;
    for (let i = 0; i < n; i++) { total += cardPoints[i]; if (i < w) win += cardPoints[i]; }
    let minWin = win;
    for (let i = w; i < n; i++) { win += cardPoints[i] - cardPoints[i - w]; minWin = Math.min(minWin, win); }
    return total - minWin;
  }
tests:
  - { args: [[1, 2, 3, 4, 5, 6, 1], 3], expect: 12 }
  - { args: [[2, 2, 2], 2], expect: 4 }
  - { args: [[9, 7, 7, 9, 7, 7, 9], 7], expect: 55 }
  - { args: [[1, 1000, 1], 1], expect: 1, hidden: true }
  - { args: [[1, 79, 80, 1, 1, 1, 200, 1], 3], expect: 202, hidden: true }
  - { args: [[5], 1], expect: 5, hidden: true }
explain: "The problem does not mention windows at all. Looking at what is **left behind** reveals one. Re-framing the question is a recognition skill of its own."
hints:
  - "Take a small example and look at the cards you did not take. What shape do they form?"
  - "Maximising what you take is the same as minimising what you leave."
  - "The cards left behind are a window of fixed length n − k."
```

## Guided interview problem {guided}

Your first idea here will probably fail. Notice when, and say the switch.

```ex
type: interview
title: Maximum Length of Subarray With Positive Product (LeetCode 1567)
q: "Return the length of the longest subarray whose product is positive. Example: `[0,1,-2,-3,-4]` → 3 (`[1,-2,-3]`)."
model:
  clarify: |
    - Zeros make a product 0, which is not positive.
    - n up to 10⁵; values up to 10⁹ in size, so products overflow immediately.
  brute: "Every subarray with a running product: O(n²) and the product overflows. Abandon computing products: only the **sign** matters."
  optimize: |
    State machine over two lengths ending at i: `pos` = longest subarray ending at i with a positive product, `neg` = with a negative product. If x > 0: pos = pos + 1, neg = neg ? neg + 1 : 0. If x < 0: swap them: new pos = neg ? neg + 1 : 0, new neg = pos + 1. If x = 0: both reset to 0. Answer: max pos. This is 152's "track both extremes" idea, applied to lengths.
  edges: |
    - a single negative → 0
    - all zeros → 0
    - zeros splitting the array into segments
  complexity: "O(n) time, O(1) space."
fn: getMaxLen
starter: |
  function getMaxLen(nums) {

  }
solution: |
  function getMaxLen(nums) {
    let pos = 0, neg = 0, best = 0;
    for (const x of nums) {
      if (x === 0) { pos = 0; neg = 0; }
      else if (x > 0) { pos = pos + 1; neg = neg ? neg + 1 : 0; }
      else { const p = pos; pos = neg ? neg + 1 : 0; neg = p + 1; }
      best = Math.max(best, pos);
    }
    return best;
  }
tests:
  - { args: [[1, -2, -3, 4]], expect: 4 }
  - { args: [[0, 1, -2, -3, -4]], expect: 3 }
  - { args: [[-1, -2, -3, 0, 1]], expect: 2 }
  - { args: [[-1]], expect: 0, hidden: true }
  - { args: [[1, 2, 3, 5, -6, 4, 0, 10]], expect: 4, hidden: true }
  - { args: [[-1, 2]], expect: 1, hidden: true }
explain: "The moment to switch is when you notice the products overflow: that tells you the real information is the sign, and the sign only needs two counters."
hints:
  - "Do you need the product, or only its sign?"
  - "What changes when a negative number arrives?"
  - "Track two lengths ending here: positive and negative."
```

```ex
  - label: Heap size in the worst case
    answer: O(E)
    options: ['O(V)', 'O(E)', 'O(1)']
    why:
      O(V): "With lazy deletion a node can be pushed once per improving edge, so up to E entries."
explain: "O(log E) = O(log V²) = O(2 log V), which is why the bound is usually written with log V."
hints:
  - "How many times can a node be pushed with lazy deletion?"
```
