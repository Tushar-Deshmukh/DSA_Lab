Arrays give you positions; linked lists give you pointers; stacks and queues give you an order of access. This week is about **discipline with references**: never lose the rest of a list, always know what the top of a stack means, and never pay O(n) for an operation that should be O(1).

## The k-th node from the end {theory}

To reach the n-th node from the end in one pass, give `fast` a head start so that when it falls off the end, `slow` is exactly where you need it. For *deletion* (problem 19) you need the node **before** the target, so start both at a dummy and give `fast` n + 1 steps.

## Composing techniques: Reorder List {theory}

Reorder List (143) turns `L0 → L1 → … → Ln` into `L0 → Ln → L1 → Ln−1 → …`. None of its steps is new:

1. Find the middle with fast/slow (Day 2).
2. **Cut** the list there: the first half's last node gets `next = null`.
3. Reverse the second half (Day 1).
4. Interleave the two halves, like a merge that alternates instead of comparing.

The classic failure is step 2. If the first half's tail still points into the second half, the final list contains a cycle, and LeetCode reports a time-out or a memory error rather than a wrong answer.
