<Unit id="kruskal-cheapest-safe-edge-first" kind="theory" title="Kruskal: cheapest safe edge first">

<Include id="theory/graphs-weighted-greedy/minimum-spanning-tree" />

Why is taking the cheapest edge between two different trees always safe? Split the vertices into any two groups (a *cut*). Every spanning tree needs at least one edge crossing the cut. If an MST used a more expensive crossing edge, swapping it for the cheapest crossing edge keeps the tree connected and does not raise the total. This *cut property* is an exchange argument, the same reasoning you will use for greedy proofs in the next lesson.

<Unit id="prim-for-complete-graphs-1584" kind="theory" title="Prim for complete graphs (1584)">

In 1584 every pair of points is an edge, so E ≈ n²/2. Kruskal would sort all of them (O(n² log n)), and a heap-based Prim pushes O(n²) entries (also O(n² log n)). Prim's array version keeps `best[v]`, the cheapest known connection from each outside point to the tree, and each round scans that array once: O(n²) total, with no heap and no edge list.

<Unit id="when-dijkstras-assumption-breaks-optional-787" kind="theory" title="When Dijkstra's assumption breaks (Optional: 787)">

Problem 787 asks for the cheapest flight route using **at most k stops**. Dijkstra finalises each city at its cheapest cost, but the cheapest way to reach an intermediate city might use too many stops, while a pricier route with fewer stops is the one that can still reach the destination in time. The fix is to count flights explicitly: run k + 1 rounds of relaxation, each reading only the previous round's distances.
