<Unit id="from-bfs-to-weighted-shortest-paths" kind="theory" title="From BFS to weighted shortest paths">

BFS works on unweighted graphs because nodes leave the queue in order of distance. With weights, the order in which nodes are discovered no longer matches their distance: a path of three cheap edges can beat one expensive edge. Dijkstra restores the "process in order of distance" idea by replacing the queue with a min-heap keyed by tentative distance.

<Unit id="changing-the-cost-function-stretch-1631" kind="theory" title="Changing the cost function (Stretch: 1631)">

Dijkstra only needs one thing from the path cost: extending a path never makes it cheaper. Sums of non-negative weights satisfy that, and so does "the largest single step so far". Problem 1631 (Path With Minimum Effort) asks for the route whose **largest** height difference is smallest, so the relaxation becomes `max(d, |h[next] − h[cur]|)`.
