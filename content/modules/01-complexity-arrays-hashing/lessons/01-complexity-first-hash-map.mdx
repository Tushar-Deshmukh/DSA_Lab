<Unit id="intuition-count-then-ignore-constants" kind="theory" title="Intuition: count, then ignore constants">

Complexity is a way to compare algorithms without running them. Count how many basic steps the algorithm takes as a function of the input size n, then keep only the term that dominates for large n. `3n + 20` becomes O(n); `n²/2 + 5n` becomes O(n²). Constants matter in practice, but a better growth rate wins by so much at interview sizes that the growth rate is what you are asked for.

The visualizer at the top of the module overview shows what that means at n = 10⁵: O(n log n) is a few milliseconds, O(n²) is a minute and a half, O(2ⁿ) never finishes.

<Unit id="counting-loop-iterations" kind="theory" title="Counting loop iterations">

Three rules cover most code:

1. **Sequential loops add.** A loop over n followed by a loop over m is O(n + m).
2. **Nested loops multiply**, when the inner loop's length does not depend on the outer one: O(n · m). If it does (`j` from `i + 1`), add up the actual counts.
3. **An index that halves or doubles** runs O(log n) times: you can only halve n about log₂ n times before reaching 1.

<Unit id="amortised-cost-and-space" kind="theory" title="Amortised cost and space">

Some operations are usually cheap and occasionally expensive. `push` on a full array allocates a bigger buffer and copies everything: O(n) for that one push. Because the buffer doubles, the expensive pushes are rare enough that n pushes cost O(n) in total, which is O(1) **amortised** per push. You will step through this in lesson 2.

**Space** means *auxiliary* space unless someone says otherwise: what your algorithm allocates on top of the input. A recursion's call stack counts. Returning a new array of size n is usually mentioned separately ("O(n) for the output").
