<Include id="theory/complexity-arrays-hashing/matrices" />

```js
const DIRS = [[1, 0], [-1, 0], [0, 1], [0, -1]];   // down, up, right, left
const inBounds = (r, c) => r >= 0 && r < grid.length && c >= 0 && c < grid[0].length;
for (const [dr, dc] of DIRS) {
  const nr = r + dr, nc = c + dc;
  if (!inBounds(nr, nc)) continue;   // check BEFORE grid[nr][nc]
  // ... use grid[nr][nc]
}
```

<Unit id="spiral-order" kind="theory" title="Spiral order">

A visited matrix works but costs O(m·n) space. Four boundaries do it in O(1): output the top row and move `top` down, the right column and move `right` left, the bottom row (if a row is left) and move `bottom` up, the left column (if a column is left) and move `left` right.

<Unit id="rotate-in-place" kind="theory" title="Rotate in place">

<Include id="patterns/matrix-layer-walking" />

Rotating 90° clockwise sends the element at `(r, c)` to `(c, n − 1 − r)`. Doing that directly needs four-way cycles of swaps. Splitting it into two simple moves is easier to get right: **transpose** (`(r, c) → (c, r)`), then **reverse each row** (`(c, r) → (c, n − 1 − r)`).

<Unit id="optional-set-matrix-zeroes" kind="stretch" title="Optional: Set Matrix Zeroes">

Problem 73 wants every row and column that contains a 0 set to 0, in O(1) extra space. Recording the zero rows and columns in two Sets is O(m + n) space and a fine first answer. The O(1) version uses the first row and first column of the matrix itself as the markers, with one extra flag for whether the first column itself must be zeroed, and processes the first row and column last so the markers are not destroyed early.
