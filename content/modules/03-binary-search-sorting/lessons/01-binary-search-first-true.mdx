<Unit id="the-boundary-idea" kind="theory" title="The boundary idea">

<Include id="theory/binary-search-sorting/binary-search-as-find-the-boundary" />

Look at `nums = [1, 2, 2, 2, 5]` and the predicate `nums[i] >= 2`. Across the array it reads `F T T T T`. The predicate is **monotone**: once it becomes true it stays true, because the array is sorted. "Where does 2 first appear?" becomes "where is the first T?", and that question always has an answer: an index from 0 to n, where n means "no T at all".

That reframing is what removes the special cases. You no longer ask "did I find it?" inside the loop. You shrink the range until it pins down the boundary, then check the boundary once, after the loop.

</Unit>

<Unit id="two-conventions-and-how-to-derive-them" kind="theory" title="Two conventions, and how to derive them">

<Include id="theory/binary-search-sorting/two-interval-conventions" />

The derivation has two parts, and you should be able to say both:

1. **The answer stays in the range.** If `pred(mid)` is true, the first true index is `mid` or earlier, so `hi = mid` keeps it. If false, everything up to `mid` is false, so `lo = mid + 1` keeps it.
2. **The range shrinks.** `mid` is always in `[lo, hi)`, so `hi = mid` makes the range smaller, and so does `lo = mid + 1`. A range that shrinks by at least one every iteration must end.
