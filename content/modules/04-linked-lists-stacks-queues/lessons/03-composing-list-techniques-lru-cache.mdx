<Unit id="composing-techniques-reorder-list" kind="theory" title="Composing techniques: Reorder List">

Reorder List (143) turns `L0 → L1 → … → Ln` into `L0 → Ln → L1 → Ln−1 → …`. None of its steps is new:

1. Find the middle with fast/slow (lesson 2).
2. **Cut** the list there: the first half's last node gets `next = null`.
3. Reverse the second half (lesson 1).
4. Interleave the two halves, like a merge that alternates instead of comparing.

The classic failure is step 2. If the first half's tail still points into the second half, the final list contains a cycle, and LeetCode reports a time-out or a memory error rather than a wrong answer.

<Callout kind="tip" title="The JavaScript shortcut">

A `Map` remembers insertion order, so deleting and re-inserting a key moves it to the end, and `map.keys().next().value` is the oldest key. That gives a 10-line LRU. Mention it as a trade-off in an interview, then implement the linked list: that is what is being tested.

</Callout>

<Callout kind="tip" title="Optional: Reverse Linked List II (92)">

Reversing positions `left..right` is this lesson's Optional problem: walk a dummy-based pointer to the node *before* `left`, then repeatedly move the next node of the segment to the segment's front ("head insertion") `right − left` times. The dummy matters because `left` can be 1.
