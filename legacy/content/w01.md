## Intuition: count, then ignore constants {theory}

Complexity is a way to compare algorithms without running them. Count how many basic steps the algorithm takes as a function of the input size n, then keep only the term that dominates for large n. `3n + 20` becomes O(n); `n²/2 + 5n` becomes O(n²). Constants matter in practice, but a better growth rate wins by so much at interview sizes that the growth rate is what you are asked for.

The visualizer at the top of the week page shows what that means at n = 10⁵: O(n log n) is a few milliseconds, O(n²) is a minute and a half, O(2ⁿ) never finishes.

## Counting loop iterations {theory}

Three rules cover most code:

1. **Sequential loops add.** A loop over n followed by a loop over m is O(n + m).
2. **Nested loops multiply**, when the inner loop's length does not depend on the outer one: O(n · m). If it does (`j` from `i + 1`), add up the actual counts.
3. **An index that halves or doubles** runs O(log n) times: you can only halve n about log₂ n times before reaching 1.

## Recursion trees {theory}

For recursive code, draw one node per call. **Time** is the number of nodes times the work in each. **Stack space** is the longest root-to-leaf path, because only one path is waiting on the stack at any moment. Step through snippet (e) and watch both numbers.

## Amortised cost and space {theory}

Some operations are usually cheap and occasionally expensive. `push` on a full array allocates a bigger buffer and copies everything: O(n) for that one push. Because the buffer doubles, the expensive pushes are rare enough that n pushes cost O(n) in total, which is O(1) **amortised** per push. You will step through this on Day 2.

**Space** means *auxiliary* space unless someone says otherwise: what your algorithm allocates on top of the input. A recursion's call stack counts. Returning a new array of size n is usually mentioned separately ("O(n) for the output").

## Dynamic arrays {theory}

@pull Arrays in JavaScript

A JavaScript array keeps its elements in a buffer with some spare capacity. `push` writes into the spare slot. When there is none, the engine allocates a larger buffer (typically about double) and copies everything over. Step through 17 pushes and watch the total work per push stay below 3:

## Read/write pointers {theory}

Many "in place" problems keep a **prefix** of the array as the answer and grow it as they scan. Two indices do the work: `read` visits every element; `write` marks where the next kept element goes. Because `write ≤ read` at all times, writing never destroys an element that has not been read yet.

## Move Zeroes: swap instead of copy {code}

Problem 283 keeps the non-zero values in their original order and pushes the zeros to the end. Swapping `nums[read]` into `nums[write]` does both at once: the zero that was at `write` moves to `read`.

@viz move-zeroes

## Count, then bucket by count {theory}

Once you have counted, the question "which values are most frequent?" sounds like a sort. But counts have a special property: they are integers between 1 and n. So use them as **indices**: put each value in `buckets[count]`, then read the buckets from the highest count downwards until you have k values. No comparison sort is needed.

## Majority element: votes that cancel {theory}

Majority Element (169) guarantees that one value appears more than n/2 times. A Map of counts solves it in O(n) time and O(n) space. Boyer–Moore does it in O(1) space: keep one candidate and a vote count; each element that matches adds a vote, each element that differs removes one, and when the votes reach zero the next element becomes the candidate.

@viz boyer-moore

```ex

    for (const x of nums) {

    }
    return candidate;
```

## Spiral order {theory}

A visited matrix works but costs O(m·n) space. Four boundaries do it in O(1): output the top row and move `top` down, the right column and move `right` left, the bottom row (if a row is left) and move `bottom` up, the left column (if a column is left) and move `left` right.

@viz spiral

```ex
type: bug
tag: The edge cases
q: "This version outputs `[1, 2, 3, 4, 3, 2]` for the single row `[[1, 2, 3, 4]]`. Click the line where the missing check belongs."
code: |
  function spiralOrder(m) {
    const out = [];
    let top = 0, bottom = m.length - 1, left = 0, right = m[0].length - 1;
    while (top <= bottom && left <= right) {
      for (let c = left; c <= right; c++) out.push(m[top][c]);
      top++;
      for (let r = top; r <= bottom; r++) out.push(m[r][right]);
      right--;
      for (let c = right; c >= left; c--) out.push(m[bottom][c]);
      bottom--;
      for (let r = bottom; r >= top; r--) out.push(m[r][left]);
      left++;
    }
    return out;
  }
bug: [8]
kind: impl
explain: "After the top row, `top` (1) is past `bottom` (0): there is no bottom row left, but this loop walks row `bottom` = 0 again, backwards. Guard it with `if (top <= bottom)`. The left pass needs `if (left <= right)` for the n × 1 case."
fix: |

    for (let c = right; c >= left; c--) out.push(m[bottom][c]);
    bottom--;
  }
  if (left <= right) {
    for (let r = bottom; r >= top; r--) out.push(m[r][left]);
    left++;
  }

  3: "The loop condition is right; the problem is inside the loop."
  4: "The top pass always runs on a valid row."

  - Trace the single-row case. Which pass outputs elements a second time?
```

## Rotate in place {theory}

@pull Pattern 1.4

Rotating 90° clockwise sends the element at `(r, c)` to `(c, n − 1 − r)`. Doing that directly needs four-way cycles of swaps. Splitting it into two simple moves is easier to get right: **transpose** (`(r, c) → (c, r)`), then **reverse each row** (`(c, r) → (c, n − 1 − r)`).

@viz rotate

## Optional: Set Matrix Zeroes {stretch}

Problem 73 wants every row and column that contains a 0 set to 0, in O(1) extra space. Recording the zero rows and columns in two Sets is O(m + n) space and a fine first answer. The O(1) version uses the first row and first column of the matrix itself as the markers, with one extra flag for whether the first column itself must be zeroed, and processes the first row and column last so the markers are not destroyed early.

```ex
  function generateMatrix(n) {
```
